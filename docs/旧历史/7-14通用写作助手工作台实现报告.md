# 通用写作助手工作台实现报告

> 更新日期：2026-07-14

## 一、实现结论

通用写作助手已经接入现有智能体工作台，并作为默认智能体开放。作者可以在同一入口处理从简短事实询问、局部分析，到多章节规划、创作和审校等任意规模的小说写作请求；原有正文知识沉淀 Workflow 保留独立入口和既有交互，没有迁移到通用 Agent Runtime。

本次页面实现使用项目已有组件和图标体系，没有新增前端依赖。

## 二、主要交付

- 新增通用写作助手任务表单，支持任务目标、选区、单章、多章、全文等正文范围，以及直接上下文和约束。
- 外部资料访问默认关闭，只有作者明确勾选后才将许可传给 Runtime。
- 任务通过后台接口启动，页面轮询独立运行记录并展示生命周期、当前计划和节点进度。
- 支持查看最近任务、打开历史任务、刷新、取消和删除运行记录。
- Runtime 需要补充信息时，页面展示澄清问题并允许作者继续任务。
- Runtime 请求持久化写入时，页面展示操作、中文作用范围、输入哈希和确定输入；高风险写操作要求作者二次确认。
- 完成后展示最终答复和来源数量，并提供复制操作。
- 工作台左侧新增统一智能体切换器；通用写作助手和正文知识沉淀各自保持独立运行记录和交互目标。
- 首页的智能体工作台说明已同步更新，不再只描述知识沉淀能力。

## 三、边界说明

- 工作台消费通用 Runtime 的独立 HTTP API，不复用知识沉淀 Workflow 的业务状态机、运行日志或评测模型。
- 页面展示的是作者执行任务所需的紧凑进度；完整动态节点监控和调用明细归入后续独立任务监控页面。
- 本次没有执行真实模型任务，以避免验收阶段产生无意义的模型调用；Runtime 的真实能力调用已由后端自动化测试覆盖。

## 四、验证结果

- `npm run lint`：通过。
- `npx tsc --noEmit`：通过。
- `npm run test:general-agent`：通过。
- 现有编辑器、知识库、模型选择和知识沉淀评测前端测试：全部通过。
- `npm run build`：通过，`/agent-workbench` 成功生成。
- `start.bat`：固定前端 `3000` 与后端 `8000` 端口启动成功；工作台和通用 Agent 运行列表接口均返回 `200`。
- 桌面浏览器验收：默认进入通用写作助手，智能体切换、任务输入和空状态正常；切换至正文知识沉淀后原功能可用，控制台无错误。
