# 通用写作助手能力层实现报告

> 更新日期：2026-07-13
> 状态：历史实现快照，不替代当前代码与已确认架构决策

## 一、实现结论

通用写作助手阶段一能力层已经完成。系统现在拥有十六个可独立调用的真实 Tool、十二个可独立执行的专业子 Agent，以及统一 Schema、异步调用协议、上下文、结果信封、权限门禁、中间产物、分层技术日志和独立评测 Profile。

本次没有实现顶层 Orchestrator、通用 Agent Runtime、动态 DAG、记忆、checkpoint/resume 或人工确认页面，也没有修改现有知识沉淀 Workflow 的业务状态机、业务日志和评测模型。

## 二、已实现的 Tool

- 小说正文与结构读取：`get_novel_structure`、`read_manuscript`、`search_manuscript`。
- 已确认知识读取：`retrieve_knowledge`、`resolve_knowledge_identity`、`list_knowledge_catalog`、`read_knowledge_cards`。
- 外部资料研究：`search_external_sources`、`read_external_source`。
- 正文与卷章结构写入：`preview_manuscript_patch`、`apply_manuscript_patch`、`create_novel_structure_items`、`update_novel_structure`、`delete_novel_structure_items`。
- 已确认知识写入：`create_confirmed_knowledge`、`update_confirmed_knowledge`。

所有 Tool 通过同一 `ToolRegistry.invoke()` 入口完成输入输出 Schema、调用方白名单、超时、外部访问许可、作者授权、幂等、结果预算和技术日志校验。正文写入使用基础内容哈希和补丁结果哈希防止静默覆盖；卷章和知识更新使用结构版本或 `updated_at` 进行并发检查；删除卷章使用二次确认并归档 Markdown，不做直接物理清除。

外部研究使用可替换的应用层后端契约，当前真实实现通过 DuckDuckGo HTML 搜索并读取公开 HTML 或纯文本页面；来源读取限制为 HTTP/HTTPS，拒绝认证 URL、本机、私有和非公开网络地址，并在每次重定向后重新校验。

## 三、已实现的专业子 Agent

- 事实与研究：`canon_evidence`、`external_research`、`narrative_summary`。
- 设定与人物：`worldbuilding`、`character`。
- 规划：`story_architecture`、`scene_planning`。
- 正文生产：`drafting`、`revision`。
- 审查：`consistency_reviewer`、`narrative_reviewer`、`style_reviewer`。

十二个专业子 Agent 各自拥有独立 Manifest、职责与非职责、Prompt、逻辑模型角色、输入输出 Schema、最小 Tool 权限、资源上限和评测 Profile。生成与修改、宏观剧情与场景规划保持拆分；一致性审查对外保持一个 Agent，内部输出覆盖世界规则、人物、时间线、因果、状态连续性和伏笔六个维度。

专业子 Agent 只调用读取 Tool，不拥有任何持久化写 Tool 权限。模型输出必须通过对应 Pydantic Schema；首次结构错误时允许一次有限修复，不进行无界自我反思。

## 四、上下文、中间产物与模型路由

Tool 和专业子 Agent 共享最小技术调用上下文，用 `task_id`、`run_id`、`call_id` 和 `parent_call_id` 形成调用树，同时传递用户目标、作者约束、业务范围、资源预算和授权引用。

专业子 Agent 输出会保存为 `lifecycle=draft` 的有类型 JSON 中间产物，包含生产者、输入哈希、内容哈希、来源引用和创建时间。下游 Agent 只能读取其 Manifest 明确接受的产物类型，因此可以实现“宏观规划到场景规划、场景规划到正文生成、审查到修改”等接力，而不会把中间态误当成正文或已确认知识。

模型通过逻辑角色路由，十二个角色都有独立配置入口。默认复用当前系统模型，也可通过 `AGENT_MODEL_ROLES_JSON` 覆盖特定角色；具体模型 ID 不写入 Agent Prompt 或业务代码。

## 五、日志与评测

能力层新增 Tool、专业子 Agent 和 LLM 三层技术调用记录，保存调用树、能力名称、状态、输入哈希、字符数、模型角色、Token、耗时、授权引用和脱敏错误。它不统一写作区单步任务、知识沉淀 Workflow 和未来 Runtime 的业务日志、状态机或评测模型。

十六个 Tool 和十二个专业子 Agent 都注册了独立评测 Profile。正文生成与正文修改、宏观剧情与场景规划分别维护指标；一致性审查在单一外部能力下保留六个分维度指标。当前已完成契约和确定性链路测试，真实业务评测集、模型对比基准和质量阈值仍需根据后续样本持续补充。

## 六、验证结果

- `uv run pytest -q`：290 个测试和 23 个子测试通过。
- `uv run mypy`：290 个源文件通过，无类型错误。
- `uv run ruff check .`：通过。
- `uv run python -m compileall -q src`：通过。
- 插件发现结果：16 个 Tool、12 个专业子 Agent。
- 固定端口健康检查：`http://127.0.0.1:8000/api/agents` 返回 200，`http://localhost:3000/home` 返回 200；复用已有项目服务，没有启动临时端口。

自动化测试实际覆盖了 Markdown 正文读取、词法搜索、补丁预览与写入、卷章创建/更新/归档、四类知识读取、已确认知识创建与更新、外部/作者授权、输入哈希、幂等冲突、模型角色覆盖、结构化输出修复、中间产物保存与类型约束接力。

## 七、当前限制与后续入口

- 作者授权、外部许可和幂等结果当前是单进程运行期状态；进入 Runtime 阶段时需要纳入 checkpoint/resume 持久化。
- 外部搜索当前依赖公开 HTML 入口，已经抽象后端契约，但仍需基于真实使用评估稳定性和替换策略。
- 第一版只读取 Markdown 正文和 MongoDB 已确认知识，不读取灵感、问题、章节摘要或待确认事实工作区。
- 向量 RAG、记忆层、顶层 Orchestrator、动态 DAG 和人工确认页面尚未实现。
- 未来 Runtime 必须组合本次已注册的真实能力，不得为演示编排临时创建假 Tool、假 Agent 或测试型 `InvocationExecutor`。
