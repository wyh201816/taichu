# 知识沉淀智能体效果评估使用报告

> 更新日期：2026-07-11
>
> 归档日期：2026-07-11
>
> 本文记录该日期已经落地的使用方式与能力边界，用于验收和追溯；当前实现以代码、`AGENTS.md` 和 `README.md` 为准。

## 1. 入口与适用对象

入口位于任务监控的“智能体任务入口”页，与“知识沉淀智能体运行监控”并列：

`任务监控 → 知识沉淀智能体效果评估`

对应页面地址为 `/task-monitor/knowledge-extraction/evaluation`。评估对象是已经完成的知识沉淀历史任务所产出的候选知识卡，而不是作者确认后写入知识库的正式卡。这样可以避免作者后续编辑覆盖智能体本身的输出质量。

当前评测集覆盖前五章的五个单章样例和一个前五章批量样例，共六个可匹配的评测范围。一次可勾选 1 至 10 个历史任务做对比。

## 2. 如何使用

1. 进入“知识沉淀智能体效果评估”。
2. 选择已确认的评测集；页面会列出与该评测集范围对应的历史任务。
3. 勾选一个或多个历史任务。默认只显示可正式评分的任务；如需排查问题，可以展开诊断任务。
4. 选择是否启用语义裁判，然后执行“评估预检”。预检会检查任务范围、正文内容哈希、候选卡快照、评测集完整性和裁判模型是否可用。
5. 预检通过后启动评估。页面会轮询展示进度；完成后可以查看总指标、单任务结果、问题类型筛选、单卡差异和裁判审计记录。
6. 对有保留价值的结果执行“确认评估报告”；无效或不再需要的结果可以废弃。废弃记录不会继续出现在普通历史列表中。

当语义裁判模型暂时不可用时，可以关闭“语义裁判”后运行仅确定性评分；若启用了语义裁判，则系统会在预检或创建时明确阻止任务，不会静默把方案 B 降级成不完整结果。

## 3. 这套评估能做什么

### 3.1 对比实际输出与期望输出

系统将历史任务中的候选卡快照与评测集中的期望知识卡做一对一匹配。匹配依据是知识类型、实体身份和可比较字段，而不是 JSON 数组位置或一次性运行编号，因此同一批任务可以稳定复查。

它会识别并展示：

- 漏提取：期望存在、任务没有抽取到的知识卡。
- 多提取：任务抽取了、期望集中没有的知识卡。
- 字段不同：已匹配卡片的结构字段、摘要或来源信息不一致。
- 证据问题：引用原文未定位、证据不足或期望证据未覆盖。
- 语义问题：内容虽然形式上匹配，但有关键事实遗漏、无来源断言或事实矛盾。
- 裁判意见不一致：语义裁判结果与确定性判断之间需要人工复核的情况。

### 3.2 提供可量化的质量指标

结果不会只给一个黑盒总分。页面会同时展示可追溯的原始维度，包括：

- 候选识别：精确率、召回率、微平均 F1、宏平均 F1。
- 结构质量：结构字段得分、Schema 合规率。
- 证据质量：证据得分、已抽取证据的可靠性、期望证据覆盖度。
- 负样本抑制：对不应生成知识卡内容的抑制得分。
- 语义质量：语义正确性、语义得分和裁判覆盖率。
- 任务完整性：执行覆盖率、歧义数、严重风险数、事实矛盾数、无来源断言数和关键事实遗漏数。

综合参考分会与上述各维度一同展示，便于判断问题是“没抽到”“抽多了”“字段不准”还是“说得不可信”。

### 3.3 保留可审计的差异与上下文

创建评估时，系统会冻结当时的任务输出、评测集、正文内容、评分参数、模型身份和裁判 Prompt 契约。后续即使正文、评测集或模型配置发生变化，历史结果仍可追溯到当次比较的真实输入。

对于每一条差异，用户可以查看期望卡、实际卡、字段差异、证据差异、裁判结论和裁判调用记录。裁判记录保留输入、原始响应、解析结果、错误与时间信息，方便定位模型质量问题或复查裁判结论。

### 3.4 支持模型与工作流的回归比较

同一个评测集可以用于评估不同时间生成的历史任务。结合任务中记录的真实生成模型身份、Prompt 契约和工作流输出快照，可以比较模型切换、Prompt 调整、质量闸门修改或批处理编排调整前后的效果，而不需要重新运行旧任务。

系统也会标识生成模型与裁判模型是否相同或身份未知，避免把自评结果误当作独立评判。

### 3.5 支持故障恢复和结果管理

评估在后台执行，页面持续显示运行与裁判进度。若评估在语义裁判阶段出现可重试的失败或带警告完成，可以基于原始冻结快照重试；系统会校验裁判模型和 Prompt 契约未改变，防止“重试”悄悄换成另一套评分标准。

评估结果与知识库事实分离：它不会自动修改候选卡，也不会把评分结果写入 MongoDB。

## 4. 适合回答的问题

这套能力适合用来回答以下问题：

- 某次知识沉淀任务是否漏掉了重要角色、地点、势力或物品？
- 任务产出中有多少无效或过度抽取的候选？
- 提取到的卡片字段、摘要和原文证据是否可靠？
- 修改 Prompt、模型或质量闸门以后，质量有没有实际提升？
- 批量任务是否因个别章节失败而降低了整体可评性？
- 当前低分究竟来自候选识别、结构填写、原文证据还是语义表述？

## 5. 当前边界与人工复核要求

- 当前只覆盖知识沉淀智能体及已纳入评测集的章节范围，不对任意历史任务做无金标评分。
- 正式评分要求任务范围与正文内容哈希和评测集一致；正文改动后需重新生成任务或更新并确认评测集。
- 语义裁判只审查确定性匹配成功的卡片，不能改变匹配关系、补造金标或自动修正知识卡。
- 裁判分数是质量参考，不替代作者对关键设定的确认。出现严重风险、矛盾、无来源断言或裁判分歧时，仍应逐条查看差异。
- 评测集与裁判阈值需要持续人工校准。当前已提供校准样例和运行脚本，但“已确认的高质量阈值”仍需由两位独立审阅者完成标注核对和裁决后再写入运行结论。

## 6. 结论

效果评估把“任务是否跑完”的运行监控扩展为“输出是否正确、为什么不正确、以后是否变好”的质量闭环。它的作用不是替作者自动定稿，而是用可复现指标、可查看差异和可追溯快照，为知识沉淀智能体的持续优化提供证据。
