# 7-19 通用写作助手运行时记忆与上下文压缩报告

> 记录日期：2026-07-19  
> 状态：已按作者重新定义的“会话、请求次数、自动运行记忆和五层上下文”完成纠偏  
> 性质：历史实现与验证快照，不作为小说事实源

## 一、纠偏结论

此前实现把“对话轮次”混同为每次独立运行，并把旧运行缺失的 `conversation_id（会话标识）` 回退成各自的 `run_id（运行标识）`。这会把同一个前端对话窗口中的连续请求拆成多个“最近对话”。此前运行记忆还错误引入了草稿、确认、拒绝生命周期和作者确认入口，与运行时自动记忆的产品含义不一致。

本次纠偏后：

- 一个侧栏“新对话”窗口唯一对应一个 `conversation_id（会话标识）`。
- 窗口内每次用户请求对应一次独立运行，拥有自己的 `run_id（运行标识）`、`parent_run_id（父运行标识）` 和递增的 `request_index（请求序号）`。
- 只有用户点击“新对话”才创建新会话；刷新页面后自动打开最近会话，普通发送不会静默创建新会话。
- 前端统一显示“N 次”，不再显示“N 轮”。这里“一轮”指一个完整对话窗口，“一次”指该窗口中的一次用户请求。
- 运行记忆完全由 Runtime（智能体运行时）自动维护，不再有草稿、确认、拒绝生命周期，也不要求作者确认。
- 上下文固定分为稳定背景、工作记忆、相关记忆、过程历史、当前请求五层。
- 外层运行图使用 LangGraph 节点检查点恢复；已成功图节点不会因服务重启或异常恢复而重复执行。

## 二、会话身份关系

```text
conversation_id（会话标识）
├── 第 1 次请求：run_id A，request_index=1
├── 第 2 次请求：run_id B，request_index=2，parent_run_id=A
└── 第 3 次请求：run_id C，request_index=3，parent_run_id=B
```

旧数据迁移规则：

1. 旧运行缺少 `conversation_id` 时，优先使用共同的 `task_id（任务标识）` 作为会话标识。
2. 若错误的会话标识指向某个旧 `run_id`，沿该运行的原始 `task_id` 解析到规范会话标识。
3. `request_index` 可从累计用户消息数恢复。
4. 当前开发机上原本被拆开的“你好，你是谁”“你都能干什么”“正文第 6 章讲的什么”“正文第 7 章讲的是”以及后续两次请求，已经归并到同一个 `general_conversation_20260718_080855_cec285` 会话，共 6 次请求。
5. 旧版上下文快照与五层结构不兼容时自动失效，下一次需要上下文时重新组装，不把旧结构伪装成新结构。

## 三、自动运行记忆

运行记忆保存在 `project_assets/derived/general_agent_memory/`，可重建词法索引保存在 `project_assets/generated/agent_memory_indexes/`。

每条记忆保存：

- `kind（记忆类型）`；
- 短摘要；
- 来源运行、正文来源和产物引用；
- `created_request_index（创建请求序号）`；
- `expires_after_request_index（退出上下文的请求序号）`；
- 内容校验和、更新时间和 `deleted_at（删除时间）`。

记忆类型包括：

- `user_instruction（用户指令）`：作者硬约束和澄清修正；
- `task_summary（任务摘要）`：一次请求完成后的短结果摘要；
- `resource_summary（资源摘要）`：读取章节、文件或产物后的短摘要与引用；
- `work_note（过程笔记）`：少量下一次请求大概率还会用到的过程状态；
- `unresolved_issue（未解决问题）`：尚待澄清或修复的事项；
- `fact_reference（事实来源引用）`：只作重新取证提示，不能代替正文或知识卡。

自动写入边界：

- 第一次请求创建后，用户硬约束即可进入工作记忆。
- 读取章节、文件或长节点输出后，只写入短摘要与稳定引用，不复制正文全文。
- 普通计划理由不会无条件常驻记忆；只有待澄清问题等确有后续价值的状态才写入。
- 资源摘要默认在创建后的第 5 次请求后退出当前上下文，过程笔记默认在第 3 次请求后退出；用户指令和任务摘要使用更长保留策略。
- 过期表示不再进入当前上下文，不是小说事实删除，也不需要作者操作。
- 前端提供来源查看和手动删除，用于处理自动摘要错误；没有确认、拒绝按钮。

## 四、五层上下文

`ContextAssembler（上下文组装器）` 从当前会话第一条请求开始组装以下结构，后续规划、重规划和校验使用同一结构并持续更新：

1. 稳定背景：Agent 角色、真实能力调用规则、正文与结构事实边界、写入授权规则。
2. 工作记忆：任务摘要、近期资源摘要、少量过程笔记、当前计划摘要、节点摘要和未解决问题。
3. 相关记忆：根据当前请求从仍有效的运行记忆中检索少量相关内容；不会把全部历史记忆塞入 Prompt（模型输入指令与上下文）。
4. 过程历史：之前的用户与助手消息、节点和工具过程证据；当前请求不会在这里重复一份。
5. 当前请求：当前用户请求、用户约束和页面传入的正文范围；必须完整保留。

运行记忆不是小说事实。涉及人物、设定、时间线和情节事实时，Agent 仍必须读取 Markdown 正文或通过统一召回回读 MongoDB 当前已确认知识卡。

## 五、预算与固定裁剪顺序

Prompt 是受预算约束的运行资源。总预算不足时使用固定顺序：

1. 先移除相关记忆；
2. 再把过程历史压成结构摘要，并从最旧过程开始裁剪；
3. 再按过程笔记、资源摘要、任务摘要、未解决项、历史用户指令的顺序收缩工作记忆，同时收缩节点与计划摘要；
4. 最后才收缩稳定背景，并至少保留核心角色声明；
5. 当前请求、当前约束和当前范围不截断。

若完整当前请求本身已经超过总预算，系统返回明确错误，要求缩小选区或拆分请求，不会静默截断正文后继续生成。

压缩器失败时使用确定性安全摘要，至少保留当前请求、用户指令、来源引用、未解决问题和下一步条件。

## 六、LangGraph 恢复

- 业务运行快照仍保存在 `project_assets/derived/general_agent_runs/`，用于任务列表、状态、结果和能力节点审计。
- LangGraph 节点检查点保存在 `project_assets/derived/general_agent_graph_checkpoints/`。
- 每个运行以 `run_id` 作为 LangGraph 的 `thread_id（线程标识）`。
- LangGraph 保存通道值、中间写入和父检查点链，服务新实例可以加载同一线程并从待执行节点继续。
- 外层图已成功节点不重跑；外层 `execute_dag（执行能力图）` 节点若在内部中断，业务运行快照继续保证已成功能力节点被跳过。
- 删除运行时同步删除对应 LangGraph 线程检查点。

## 七、前端行为

- 最近对话显示“已完成 N 次 日期”，不再显示“N 轮”。
- 页面首次加载自动打开最近会话，避免刷新后因空会话标识误开新对话。
- 发送请求时显式传入 `start_new_conversation（开启新对话）`：只有新对话模式传 `true`；继续会话必须同时传入既有会话标识。
- 运行记忆面板显示记忆类型、第几次请求自动记录、何时自动退出上下文及来源引用。
- 面板没有确认和拒绝操作，只保留手动删除。

## 八、验证门禁

自动测试覆盖：

- 会话内两次请求保持同一会话标识、父运行链和递增请求序号；
- 历史回退按共同任务标识归并；
- 自动记忆无生命周期、跨会话隔离、相关选择、按请求序号过期、软删除和损坏索引重建；
- 五层上下文结构、固定预算、当前请求不截断、压缩失败安全摘要和快照复用；
- LangGraph 在第二节点失败后，使用新的持久化存储实例从第二节点恢复，第一节点调用次数保持为 1；
- 前端类型检查、通用 Agent 显示逻辑测试和 ESLint（代码规范检查）。

## 九、结论

本次纠偏后的设计与作者定义一致：会话窗口负责长期身份，一次用户请求负责一次运行；运行记忆是自动维护的工作状态；模型上下文以五层结构按固定优先级使用预算；异常恢复依赖 LangGraph 节点检查点，并由业务运行快照补充能力 DAG 的细粒度跳过语义。
