# 学习资料说明

本目录保存面向开发者的太初实现学习资料。它的目的不是替代源码、接口契约或项目规则，而是把某个实现主题讲清楚，让第一次接触和隔一段时间回来复习的人都能顺着主线建立完整理解。

## 资料边界

- 主题应围绕太初的具体实现问题，例如一次请求如何流转、某类状态如何保存、一个模块怎样与上下游协作。
- 写作前必须直接核对当前源码、测试、配置和真实运行结果；如果资料讲的是尚未落地的目标实现，必须明确标出事实与设想的边界。
- 用户与 Codex 多轮讨论形成的未来功能计划统一放入 `docs/已讨论功能/`；学习资料只解释实现机制，不承担未来产品计划的权威入口职责。
- 已废弃的方案不写入本目录，应放入 `docs/旧历史/`。
- 普通学习文章及其配套文件保留日期前缀；只有本目录的 `说明.md` 不加日期，也不维护“更新日期”。普通资料如需标明实现基线，可以在正文保留有追溯价值的日期。主题名称应直接说明读者能学到什么。

## 后续生成风格

后续为太初生成某个实现的学习资料时，统一采用以下表达方式：

1. 先说明读者对象和读完后能够回答的问题，再用一句话给出主题的核心判断。
2. 先画出全貌或主线，再沿一条真实请求、数据或状态流从入口讲到出口，避免从零散文件列表开始。
3. 每一部分同时回答“它做什么”“为什么这样设计”“与上下游怎样衔接”，不只复述类名和函数名。
4. 用清楚、自然的中文解释技术概念；保留必要的英文术语和代码标识，但第一次出现时说明其含义。
5. 结合当前项目的真实代码入口、关键片段、目录树、表格或流程图，让抽象结论能够回到源码验证。
6. 明确区分控制流、数据或状态、持久化、验证证据等不同职责，主动解释容易混淆的边界。
7. 如实写出取舍、限制和可改进方向，但不得把设想写成已经落地的能力。
8. 结尾提供推荐的源码阅读顺序和一段可用于复述的简明总结，方便学习、回顾和交流。

学习资料不要求机械套用固定章节。主题较小时可以缩短结构，但必须保留“真实主线、职责边界、设计原因、源码入口、验证依据”这五类信息。
