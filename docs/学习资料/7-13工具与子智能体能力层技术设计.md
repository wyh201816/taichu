## 一、阶段一落地结果

当前代码已经具备：

- 十六个生产 Tool 及统一 `ToolManifest`、调用方白名单、权限、超时、幂等和日志门禁。
- 十二个专业子 Agent 及独立 `SubagentManifest`、异步 Handler、Prompt、模型角色和输出 Schema。
- 调用上下文、技术结果信封、Tool/子 Agent/LLM 分层技术日志。
- 外部访问许可、作者写入授权、输入哈希、二次确认和进程内幂等控制。
- 有类型中间产物的派生层持久化、稳定引用和受类型约束的下游接力。
- 二十八个独立能力评测 Profile，以及真实正文、卷章和知识读写的自动化测试。
- 现有 Workflow 使用的 `AgentManifest`、`AgentRegistry` 和 LangGraph 构建协议。
- `CapabilityContext` 应用能力注入。
- `VectorGraphRAGService` 提供正文片段与已确认知识卡的统一证据检索。
- `ChapterService`、`OutlineService`、`KnowledgeService` 等可复用应用服务。

当前仍不属于阶段一或需要后续补强的内容：

- 顶层 Orchestrator、通用 Agent Runtime、动态 DAG、记忆和 checkpoint/resume。
- 写入授权、幂等记录随 Runtime checkpoint 持久化；当前只保证单进程运行期语义。
- 各专业子 Agent 的业务评测数据集、模型基准和质量阈值持续补充。
- 技术日志的长期保留、归档和监控页面。

当前 `outline.json` 只保存卷章树、标题和路径，不保存剧情大纲正文。因此第一版使用“小说结构读取”和“卷章结构写入”命名，不把现有卷章树错误描述成剧情大纲。

## 二、什么应该成为 Tool

一个能力只有同时满足以下条件时才注册为 Tool：

- 在产品运行时可能由高层编排 Agent 或授权子 Agent 自主选择调用。
- 能力具有稳定、可复用的业务边界和强类型输入输出。
- Handler 不包含 LLM 专业判断，能够通过应用服务确定性执行。
- 调用需要独立权限、预算、错误语义、审计或副作用控制。

以下内容不注册为 Tool：

- 用户问题、当前选区、当前章节、作者约束和运行预算：由调用上下文直接传入。
- Prompt 渲染、Schema 校验、JSON 解析、字数和句长统计、Diff、哈希、Token 统计：由应用服务、Agent Handler 或 Runtime 自动执行。
- 页面按钮和 HTTP API：它们是交互与调用入口，可与 Tool 复用同一个应用服务，但不是 Tool 本身。
- 续写、改写、设定设计、剧情规划和审查：需要 LLM 专业判断，属于子 Agent。
- 修改太初代码、数据库 Schema、迁移和前端按钮：属于项目外部 Code Agent 或开发者，不属于通用写作助手运行时能力。

## 三、统一 Manifest 与调用协议

### 1. ToolManifest

现有 `ToolManifest` 已包含名称、说明、输入输出 Schema、所需应用能力和暴露范围。第一版需要补充或通过等价稳定契约表达：

- 副作用等级：只读、预览、持久化写入、高风险写入。
- 调用方策略：高层编排 Agent、允许的专业子 Agent 或仅内部消费者。
- 外部访问策略：是否要求本次任务存在显式外部访问许可。
- 作者授权策略：是否要求写入授权、二次确认或预览结果。
- 幂等策略、默认超时、结果预算和可重试性。
- 参数与结果的脱敏审计摘要规则。

### 2. SubagentManifest

通用子 Agent 使用独立 `SubagentManifest`，不复用现有知识沉淀 Workflow 的图构建生命周期。第一版至少表达：

- 稳定名称、中文标签、职责和明确非职责。
- 输入 Schema、输出 Schema 和可产生的中间产物类型。
- 逻辑模型角色和可独立配置的默认模型映射。
- 允许调用的最小 Tool 集合。
- 可接受的正文范围、事实来源和上游产物类型。
- Token、Tool 调用数、超时、重试和内部修订上限。
- 是否支持流式输出，以及输出校验失败后的有限修复规则。

子 Agent 对外统一暴露异步 Handler。简单 Agent 可直接执行一次或有限次数 LLM 调用；复杂 Agent 可在 Handler 内封装 LangGraph 子图，但调用方不得取得原始 `CompiledStateGraph`，也不得同时依赖 Handler 和 Graph 两套协议。

### 3. 调用上下文与结果信封

Tool 和子 Agent 共享最小技术调用上下文，但保留各自业务输入输出 Schema。调用上下文至少包含：

- `task_id`、`run_id`、`call_id`、`parent_call_id`。
- 调用方身份、当前能力名称和当前阶段。
- 用户目标、当前选区或章节等业务范围。
- 作者约束、输出要求和稳定来源引用。
- 截止时间、Token、字符数、Tool 调用数和重试预算。
- 可选外部访问许可和作者写入授权引用。

统一结果信封只承载技术状态、领域结果、来源引用、中间产物引用、警告、错误和调用记录引用，不把所有 Agent 的领域输出压成一个无类型 JSON 对象。

## 四、第一版十六个 Tool

### 1. 小说正文与结构读取

| Tool | 输入边界 | 核心输出 | 第一版实现 |
|---|---|---|---|
| `get_novel_structure` | 可选卷、章节状态和分页条件 | 卷章树、章节 ID、顺序、标题、字数、状态、当前章节和结构版本 | 复用 manifest 与 outline 应用服务，统一重复字段 |
| `read_manuscript` | 章节 ID、顺序范围或稳定正文引用；字符预算 | 带章节、位置、内容哈希和截断信息的正文块 | 读取 Markdown，不做语义改写或模型摘要 |
| `search_manuscript` | 查询词、可选卷章范围、最大命中数和摘要预算 | 带章节、位置、原文摘录、匹配原因和排序的证据命中 | 第一版确定性词法扫描，后续可替换为可重建索引或混合检索 |

`read_manuscript` 用于已知位置读取，`search_manuscript` 用于未知位置发现；不得用全书无预算读取替代正文搜索。

### 2. 已确认知识读取

| Tool | 输入边界 | 核心输出 | 第一版实现 |
|---|---|---|---|
| `retrieve_knowledge` | 问题、辅助上下文、知识类型、Top K 和字符预算 | 相关知识卡、排序、匹配原因、截断和召回记录引用 | 复用统一召回层相关性模式 |
| `resolve_knowledge_identity` | 知识类型、名称和别名 | 唯一命中、无命中或歧义候选及原因 | 复用统一召回层身份模式，不允许静默选择歧义实体 |
| `list_knowledge_catalog` | 知识类型、分页、排序和结果预算 | 已确认知识的轻量目录项和分页信息 | 基于目录快照能力，强制分页和数量上限 |
| `read_knowledge_cards` | 一个或多个稳定卡片 ID | 完整已确认知识卡、缺失 ID 和版本信息 | 复用 `KnowledgeService`，默认排除草稿、拒绝和软删除记录 |

四个 Tool 共享统一 retrieval API、范围守卫、技术遥测和可替换后端，但分别拥有调用 Schema、空结果语义和评测指标。未来向量、图谱、混合检索和 Agentic RAG 是内部策略，不把四个业务能力重新合并成一个含混的万能 Tool。

### 3. 外部资料研究

| Tool | 输入边界 | 核心输出 | 第一版实现 |
|---|---|---|---|
| `search_external_sources` | 明确研究问题、来源偏好、时间范围、结果上限和外部访问许可 | 标题、来源、发布时间、摘要、链接和搜索记录引用 | 使用真实外部搜索能力，不提供占位结果 |
| `read_external_source` | 已选来源链接或搜索结果引用、读取预算和外部访问许可 | 来源元数据、正文摘录、可引用片段、截断和读取失败原因 | 真实读取来源；禁止绕过许可直接访问外部网络 |

外部研究默认不可用。只有用户明确要求联网、外部研究或核实外部资料时，Runtime 才能在本次任务范围内签发外部访问许可。专业 Agent 不得根据“可能有帮助”自行扩大外部访问范围。

### 4. 正文和卷章结构写入

| Tool | 输入边界 | 核心输出 | 第一版实现 |
|---|---|---|---|
| `preview_manuscript_patch` | 目标章节、基础内容哈希和结构化补丁操作 | 规范化补丁、差异预览、冲突和预计新哈希 | 无副作用；与真实应用 Tool 使用同一补丁校验器 |
| `apply_manuscript_patch` | 预览后补丁、作者授权、基础哈希和幂等键 | 新正文引用、新哈希、实际差异和写入审计引用 | 真实写入 Markdown；哈希变化时拒绝覆盖 |
| `create_novel_structure_items` | 新卷或章节的确定字段、目标位置、作者授权和幂等键 | 新建对象、结构版本和必要的 Markdown 引用 | 复用结构应用服务；支持批量创建但保持明确原子结果 |
| `update_novel_structure` | 目标对象、重命名、顺序或状态变更、期望结构版本和作者授权 | 更新对象、结构差异和新版本 | 不承担正文修改 |
| `delete_novel_structure_items` | 目标卷章、影响摘要、二次确认授权、期望结构版本和幂等键 | 归档位置、受影响对象和新结构版本 | 使用现有归档删除语义，不直接物理清除 Markdown |

创建、更新和删除分成三个 Tool，因为副作用、授权强度、冲突语义和恢复方式不同；它们不是按前端按钮机械拆分。

### 5. 已确认知识写入

| Tool | 输入边界 | 核心输出 | 第一版实现 |
|---|---|---|---|
| `create_confirmed_knowledge` | 作者确认后的知识候选、来源引用、授权和幂等键 | 新知识卡、冲突信息和写入审计引用 | 通过 Schema、来源、冲突和生命周期校验后调用应用服务写 MongoDB |
| `update_confirmed_knowledge` | 目标卡片 ID、作者确认后的字段变更、期望版本、合并方式、授权和幂等键 | 更新知识卡、字段差异和写入审计引用 | 采用并发检查；参数变化后原授权失效 |

第一版不提供知识删除 Tool。知识提案本身是子 Agent 输出和 Runtime 中间产物，不通过 Tool 保存；作者确认后才生成写 Tool 的确定输入。

## 五、第一版十二个专业子 Agent

下表中的 Tool 权限使用简称：`N` 表示三个小说正文与结构读取 Tool，`K` 表示四个已确认知识读取 Tool，`E` 表示两个外部研究 Tool。所有写 Tool 只允许高层编排 Agent 在授权后调用，专业子 Agent 不直接持久化数据。

| 子 Agent | 稳定职责 | 主要结构化输出 | 最小 Tool 权限 | 独立评测重点 |
|---|---|---|---|---|
| `canon_evidence` | 小说内部事实问答、原文定位、事件链和不确定性分析 | 结论、证据引用、冲突证据、未知项 | N、K | 证据正确率、引用完整性、无依据断言率 |
| `external_research` | 明确授权后的外部资料搜索、阅读和来源综合 | 研究结论、来源、分歧、时效性和可信度说明 | E | 来源可访问率、引用准确率、来源多样性、越权率 |
| `narrative_summary` | 章节、范围、人物经历和事件阶段的归纳 | 摘要、关键事件、人物变化、未解决事项、来源 | N、K | 关键信息召回、事实忠实度、压缩率、遗漏率 |
| `worldbuilding` | 世界规则、境界、功法、势力、地点和物品设计分析 | 设定提案、规则、代价、约束、冲突风险 | N、K | 内部自洽、与已确认事实兼容、可扩展性 |
| `character` | 人物动机、性格、能力、关系、成长和语言行为边界 | 角色分析或提案、关系变化、行为约束、风险 | N、K | 动机连贯、人设一致、关系合理、角色区分度 |
| `story_architecture` | 卷级、阶段级和跨章节宏观剧情架构 | 阶段目标、主支线、冲突升级、伏笔和依赖 | N、K | 长线因果、结构完整、冲突递进、伏笔可回收 |
| `scene_planning` | 章节、场景和叙事节拍规划 | 场景目标、节拍、视角、信息释放和转场 | N、K | 可执行性、节拍清晰、承接关系、目标覆盖 |
| `drafting` | 新写、续写和扩写正文候选 | 正文候选、使用约束、来源引用、风险说明 | N、K | 新内容质量、上下文承接、推进效果、目标长度 |
| `revision` | 保留原意和事实约束下的改写、缩写、润色与调整 | 修改后正文、修改说明、保留约束、风险 | N、K | 原意保留、非目标改动率、修改目标完成度 |
| `consistency_reviewer` | 设定、人物、时间线、因果、空间和状态连续性检查 | 分维度问题、严重度、证据、冲突项和修改方向 | N、K | 各维度检出率、误报率、证据充分性 |
| `narrative_reviewer` | 节奏、冲突、信息释放、悬念、转折和理解成本审查 | 叙事问题、影响、证据、严重度和修改方向 | N、K | 叙事问题检出、建议针对性、维度覆盖 |
| `style_reviewer` | 措辞、句式、重复、视角、人物口吻和文风一致性审查 | 语言问题、原文摘录、风格维度和修改方向 | N、K | 风格问题检出、误报、文风约束一致性 |

### 一致性审查的内部维度

`consistency_reviewer` 对外只有一个 Manifest、一个 Handler 和一个输出 Schema。内部第一版必须明确以下检查定义：

- 已确认设定与世界规则一致性。
- 人物动机、能力、口吻和行为一致性。
- 时间线、事件顺序和年龄时长一致性。
- 因果关系、前置条件和剧情逻辑一致性。
- 人物、物品、能力、伤势和空间位置的状态连续性。
- 已建立伏笔、承诺和回收状态的一致性。

第一版可以通过一个 Prompt 中的独立检查模块执行；后续可以在同一外部契约内并行化或使用内部子图。评测必须同时报告整体结果和各维度结果。

### 模型角色与路由

十二个子 Agent 都拥有独立逻辑模型角色和独立配置入口。第一版使用确定性的“模型角色到具体模型”映射，不要求先实现自适应成本路由，但不得把模型 ID 硬编码进 Prompt 或 Agent 业务代码。

`drafting` 与 `revision` 必须能够配置不同默认模型并分别评测；`story_architecture` 与 `scene_planning` 也保持独立模型映射。其他 Agent 即使暂时选择同一底层模型，也不能因此合并 Manifest、Prompt 或评测集。

## 六、上下文与中间产物

### 1. 直接传入的运行上下文

- 用户当前目标和明确要求。
- 当前选区、选区位置、当前章节 ID 和编辑器提供的稳定内容哈希。
- 作者明确约束、目标长度、输出格式和禁止事项。
- 本次调用的业务范围、资源预算和授权引用。

这些固定输入不通过 Tool 再读取。

### 2. 通过 Tool 获取的事实来源

- Markdown 正文是章节文本事实源。
- MongoDB 中 `lifecycle=confirmed` 的知识卡是结构事实源。
- 外部资料只是研究来源，不自动成为小说事实。
- 第一版不读取灵感、问题、章节摘要、待确认事实或其他创作工作区材料。

### 3. 中间产物

子 Agent 输出必须以有类型的中间产物传递，例如证据报告、剧情计划、场景计划、正文候选、修改提案和审查报告。中间产物：

- 显式标记 `lifecycle=draft`。
- 保存生产者、输入来源、内容哈希和创建时间。
- 通过稳定引用传递给下游，不把无界历史复制进每次 Prompt。
- 不因被多个 Agent 使用而成为正文或结构事实。

## 七、写 Tool 的真实启用契约

第一版写 Tool 不能只完成 Schema 或注册，必须真实执行应用层持久化并通过实际存储集成验证。能力层负责写 Tool 的输入校验、授权验证、幂等、并发检查和审计；Runtime 负责暂停任务、展示差异、接收作者确认、签发授权和恢复执行。

统一写入流程为：

1. 专业子 Agent 生成有类型的修改提案。
2. 高层编排 Agent 调用预览或确定性校验服务。
3. Runtime 向作者展示目标、范围、差异和风险。
4. 授权服务将 Tool 名称、资源范围、规范化输入哈希、使用次数和有效期写入授权凭据。
5. 高层编排 Agent 调用写 Tool。
6. 写 Tool 校验授权、基础版本或内容哈希和幂等键。
7. 应用服务执行写入，返回实际结果和新版本。
8. Runtime 保存调用结果，并把写后引用传给后续节点。

重复提交同一幂等键和相同规范化输入时返回同一已完成结果；相同幂等键对应不同输入时必须拒绝。正文或结构版本变化后，不得静默覆盖，必须重新预览和授权。

## 八、分层技术日志

能力层日志用于关联技术调用，不替代三类执行体系各自的业务日志、状态机和评测。至少需要记录：

- Agent 调用：`task_id`、`run_id`、`call_id`、父调用、Agent 名称、状态、输入输出摘要、耗时和校验结果。
- LLM 调用：Agent 调用引用、逻辑模型角色、实际模型身份、Token、费用、耗时、上游请求 ID、重试和脱敏错误。
- Tool 调用：调用者、Tool 名称、参数摘要、结果摘要、来源数量、耗时、超时、重试、副作用等级和授权引用。
- 写入调用：规范化输入哈希、资源版本、幂等键、授权校验结果和实际持久化结果。
- 外部访问：显式用户意图引用、访问许可、来源域名、搜索或读取状态和引用数量。

技术日志不得保存密钥、鉴权头或未经策略允许的完整 Prompt、模型原文和外部页面全文。具体物理路径、保留周期和回放快照策略仍待实现时确认。

## 九、第一版评测方案

### Tool 评测

- `get_novel_structure`：目录完整性、顺序正确性、当前章节和版本一致性。
- `read_manuscript`：章节定位、正文完整性、哈希正确性、预算截断和来源引用。
- `search_manuscript`：固定查询集上的命中率、原文定位准确率、排序质量和空结果语义。
- `retrieve_knowledge`：Precision@K、Recall@K、排序质量、事实范围和截断。
- `resolve_knowledge_identity`：唯一身份准确率、歧义检出率、错误合并率和别名覆盖。
- `list_knowledge_catalog`：类型过滤、分页完整性、稳定排序和预算边界。
- `read_knowledge_cards`：ID 定向读取准确率、缺失语义和生命周期隔离。
- 外部研究 Tool：显式许可拦截、来源可访问率、来源元数据完整性、引用可追溯性和超时。
- 写 Tool：未授权拒绝、输入变化后授权失效、基础版本冲突、幂等重放、真实持久化结果、归档删除和审计完整性。

### 子 Agent 评测

每个子 Agent 使用独立数据集、独立指标和独立模型对比，不用一个“通用写作质量分”替代专业评测。所有 Agent 共用以下底线指标：

- 输出 Schema 合规率。
- 任务目标完成率。
- 来源引用和事实落地率。
- 越权 Tool 调用率。
- 职责越界率。
- 超时、重试和资源预算遵守率。

专业指标以第五节表格为准。`drafting` 和 `revision` 必须分别比较模型；一致性审查必须同时给出整体与分维度指标。

## 十、第一版实现深度

- 每个 Tool 使用真实应用服务和真实数据源，不返回演示数据。
- 每个子 Agent 至少执行一次真实 LLM 调用，拥有独立 Prompt、输出 Schema、模型角色和评测入口。
- 输出解析或 Schema 校验失败可进行一次有上限的格式修复；不得无界自我反思。
- 子 Agent 第一版不要求内部 LangGraph，普通异步 Handler 足以承载单次或有限调用。
- 外部研究能力真实存在但默认不可用；没有显式用户许可时必须在调用前拒绝。
- 写 Tool 第一版真实启用；没有合法作者授权时必须拒绝，而不是降级成“假成功”或只返回提案。
- 第一版不实现创作工作区读取、运行时记忆、上下文压缩、向量 RAG 或顶层多 Agent 编排。

## 十一、已完成的实施顺序

1. 扩展 Tool 与 `SubagentManifest` 稳定契约，建立统一异步调用、上下文、结果信封和技术日志接口。
2. 先实现正文结构读取、正文读取、正文搜索和四个知识读取 Tool，并完成独立评测。
3. 实现外部搜索、外部来源读取及显式用户许可门禁。
4. 实现授权验证、预览、幂等和并发检查，再完成正文、卷章结构和知识写 Tool 的真实持久化。
5. 按十二个能力目录实现独立子 Agent、模型角色、最小 Tool 权限和结构化输出。
6. 为每个子 Agent 建立独立评测集和模型比较，不以某条固定任务链作为唯一验收。
7. 所有能力独立验收后，再进入通用 Agent Runtime、异步编排和动态 DAG 阶段。

## 十二、本阶段不包含

- 顶层 Orchestrator Agent、通用 Agent Runtime 和动态 DAG。
- Runtime 业务状态机、人工确认页面、checkpoint/resume、历史分支和长期记忆。
- 为演示协议创建的假 Tool、假 Agent 或独立测试型 `InvocationExecutor`。
- 现有知识沉淀 Workflow 的注册、状态机、业务日志或评测重构。
- 写作区九个单步按钮向通用 Agent 的迁移。
- 灵感、问题、章节摘要和待确认事实等创作工作区读取能力。

## 十三、后续调优与 Runtime 接入验证

- 各 Tool 的默认预算、分页、截断和错误码是否需要根据真实调用数据调整。
- 各子 Agent 的 Prompt、模型角色映射、业务评测集和质量阈值。
- 一致性审查是否需要在保持单一外部契约的前提下升级为内部有限并行。
- 外部搜索提供方的长期稳定性和可替换后端策略。
- 授权、幂等和中间产物如何纳入 Runtime checkpoint/resume。
- 技术日志的保留周期、归档、监控展示和敏感内容治理。
